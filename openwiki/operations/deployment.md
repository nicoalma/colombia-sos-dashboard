# Deployment & automation

## Vercel

The repository is imported as a Vercel project (framework preset "Other", no build command, output = repo root — the repo root *is* the site, which is why generated docs (`openwiki/`) being plain Markdown is harmless: they are just extra static files). Every push to `main` deploys production automatically, and **every pull request gets its own preview URL** — which is the review mechanism for the "propose an initiative → PR → review before merge" flow.

GitHub Pages was evaluated first and dropped: its first-time enablement needs a manual settings click (the workflow `GITHUB_TOKEN` lacks repository-administration permission), it has no PR previews, and it can never host the roadmap's API/MCP endpoints, which on Vercel are a matter of adding an `api/` directory.

## Automated data refresh (`.github/workflows/refresh-data.yml`)

Twice a day (12:00 and 00:00 UTC — 07:00/19:00 Colombia) the feed refreshes itself:

1. `scripts/check-links.mjs` probes every feed link → `link-report.json` (deterministic evidence; never mutates the feed).
2. `scripts/refresh-initiatives.mjs` calls Claude (`claude-opus-5`) with the server-side web search tool to verify each initiative and discover new ones. The merge in code — not the model — is the safety boundary: existing entries can only change `status`/`verification`/`updatedAt`; new entries are schema-validated, forced to `por_verificar`, and capped at 5 per run; nothing is deleted.
3. `scripts/validate.mjs` gates the result against the schema.
4. `peter-evans/create-pull-request` opens a PR on branch `data/refresh` with the agent's summary (`refresh-summary.md`) — a human merges, and Vercel gives the PR a preview URL.

**Required secret:** `ANTHROPIC_API_KEY` (shared with the OpenWiki workflow). Without it the refresh step fails; the link checker still runs.

## OpenWiki updates (`.github/workflows/openwiki-update.yml`)

Generated by `openwiki --init` (v0.3.3, Anthropic provider). Daily at 08:00 UTC — or manually via `workflow_dispatch` — it runs `openwiki code --update --print`, which diffs the repo against the last documented commit and refreshes `openwiki/`, `AGENTS.md`, and `CLAUDE.md`, opening a `docs: update OpenWiki` PR when something changed.

**Required secret:** `ANTHROPIC_API_KEY` (Settings → Secrets and variables → Actions). Without it the scheduled run fails at the OpenWiki step. The LangSmith secrets in the workflow are optional tracing extras.

To update docs from a laptop instead: `npm i -g openwiki && openwiki --update` with `ANTHROPIC_API_KEY` set locally.
